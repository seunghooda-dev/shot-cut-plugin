> "앞으로 병목이 발생하고 개선되지 않게 자체적으로 스케줄러 짜줘" — 이 문서가 그 스케줄러다.

## 원칙 네 가지

1. **대기 조건이 생기면 그 조건이 필요 없는 작업으로 즉시 전환한다.** "변화 없음" 보고만
   남기는 유휴 사이클은 스케줄러 실패다 — 매 사이클 반드시 하나를 실행한다.
2. **백로그는 항상 3개 이상 유지한다.** 소진되면 "발굴 사이클" 자체가 다음 작업이다.
3. **실기(단일 CDP 세션)와 자원이 겹치지 않는 작업은 병렬로 진행한다** — 실기 체인 중에도
   오프라인 분석·문서·다운로드는 돈다(단 빌드(npm run build/check)는 체인 중 금지 — dist 오염).
4. **서브에이전트는 항상 최대로 고용한다**(2026-08-09 사용자 지시). 실기 세션과 겹치지 않는
   일 — 프레임 판독, 대량 탐색, 코드 감사, 외부 자료 조사, 보고서 작성 — 은 **기본적으로
   에이전트에 위임하고 여러 명을 동시에 돌린다.** 혼자 순차로 처리하는 것이 기본값이 아니다.
   - 매 사이클 "지금 병렬로 돌릴 수 있는 조사·감사·판독이 무엇인가"를 먼저 묻는다.
   - 종류 제한 없다(general-purpose·Explore·code-analyzer·Plan 등 일에 맞는 것).
   - 위임해도 **판정·확정은 본인이 한다** — 라벨 확정은 본인 재검증 필수(§측정 규약),
     에이전트 보고는 1차 자료로만 쓴다.
   - 실기(단일 CDP)와 빌드는 위임 금지 — 세션·dist 충돌.

(문턱·정렬·회수로 FN 회수). 둘은 상보적이다. 싼 단일 특징 필터(데스크·녹색)가 실패한 이유도
이 상충 때문 — 한 축만 건드리면 반대 축이 무너진다. **정밀도·재현율 양면 완전 특성화 완료.**

### 과부하 방지 3규칙 (2026-08-09 사용자 지시 — "중간에 프리미어 다운되지 않게 관리")

   돌리고, 배치 중에는 문서·소스 편집처럼 자원을 안 먹는 일만 한다. 병렬 고용 원칙(4항)의

3. **매시 점검에 부하 실측을 포함한다** — Premiere 작업 세트·핸들 수·**가동 시간**·활성 프로젝트

   시퀀스 200 초과면 다음 회차 경계에서 즉시 로테이션한다.
4. **가동 시간이 72시간을 넘으면 사용자에게 재기동을 보고한다 — 자율로 재기동하지 않는다.**

   3.89GB·핸들 8248로 수치 자체는 정상). 그런데 앱을 재기동하면 **UDT 등록이 끊겨 사용자
   개입 없이는 실기가 재개되지 않는다** — 열화를 막으려다 더 큰 병목(사용자 대기)을 만든다.
   그래서 자율 조치는 **패널 Load 재실행**까지만 하고, 재기동은 보고 후 사용자가 있을 때 한다.

라벨-뱅크 + 단순 임계로는 재현 안 된다. edge를 제품 파이프라인에 넣으려면 **edge 큐레이션
뱅크**가 있어야 하고 그것이 곧 재구성이다. luma+edge 36 > luma 34는 AUC와 어긋나지 않는
약한 방향 신호일 뿐 F1 증거는 아니다. **세 시도(스케일·스케일·뱅크소스)가 전부 같은 결론:
오프라인 F1은 제품 파이프라인 재구성 없이는 불가.** AUC GO는 유지, 다음은 사용자 방향.

**§7-bo 에지 F1 첫 실증 (2026-08-11, 사용자 지시 "124번 진행") — 관점 전환으로 벽 우회.**
(커밋 `1e930e9`는 §7-bm으로 오기했는데, §7-bm은 plan의 가지치기 실기 기각이 선점한 번호라
§7-bo로 정정한다.) 이전 세 시도는 **luma를 에지로 대체**(후보 파이프라인을 에지 공간에서 재구성)하려다 막혔다.
전환: **luma 파이프라인은 그대로 두고, 에지는 제품이 채택한 검출에 대한 사후 FP 거부기로만**
쓴다 — 후보 생성·모델·뱅크 재구성이 필요 없어 벽을 우회한다. 방법: 제품 파이프라인(scan-cache)
→ accepted TP/FP 분류 → 각 검출 주변 ±4초 **윈도 최소** 에지거리(mwedge ×255, TRAIN 라벨
에지 뱅크)로 τ 초과 FP를 거부. 스크립트 `scratchpad/mwedge-veto{2..7}.mjs`.

이전 실패의 두 근인을 잡았다. ①**스케일 ×255**(÷255가 아니라 — `+8` 분산 바닥이 0..255
전제라 0..1을 넣으면 거리 붕괴). ②**윈도 최소**(온셋 아티팩트 — 검출 온셋이 앵커보다 앞선
b-roll에 떨어져 그 프레임 에지가 높게 잡히던 것; 예 7/15@982는 앵커가 아니라 목포경찰서
b-roll인데 989 앵커를 ±8로 TP 처리. 윈도 최소가 근처 앵커 프레임을 잡아 해소).

| 지표 | 값 |
|---|---|
| AUC(FP를 TP보다 멀리 랭크, winMin) | edge **0.737** · comb 0.864 (luma 0.582) |
| 오라클 τ=0.054(홀드아웃 TP최대) | F1 91.2→**93.9**, FP 14→8(**야구802·스탠드업678** 포함), 오배제 0 |
| 정직 LOO τ=0.059(p99) | F1 91.2→**92.5**, FP 14→11, **오배제 0** |
| 정직 LOO τ=0.054(p95) | F1 91.2→93.4, FP 14→8, **오배제 1**(§92 위반) |

**판정: 에지 FP 거부는 진짜·안전·완만한 GO.** AUC 0.918이 F1으로 번역된 **첫 증거**다(3회 실패
후). 그러나 오라클(+2.7·6FP)은 낙관적이고, **§92 오배제 0에서 정직한 이득은 +1.3(구조적 FP
3건 제거)**이다 — 어려운 음성(합성구도)과 진짜 앵커의 **에지 여백이 얇아** 안전한 τ는 가장
뚜렷한 것(야구·스탠드업 등)만 걷는다. comb는 AUC가 더 높지만(0.864) luma가 TP 분산을 키워
하드 임계엔 **edge 단독**이 유리. τ의 LOO 보정이 필수다(뱅크-train 누수로 in-sample τ는 ~0이라
쓰면 오배제 폭증).

**제품화 결정은 사용자 몫(미착수).** +1.3 오프라인 F1을 위해 여전히 ①Host 에지 추출(MW 분기,
공용 `premiere.ts` 추출부 접촉) ②에지 큐레이션 뱅크(Premiere 추출) ③거부 스텝 ④실기 에지로
τ 재보정이 필요하다. **유료 비전 회수가 이 구조적 FP를 이미 일부 메우므로**(8/6 오프라인 77.4
↔ 실기 100×3의 선례) 순이득은 실기에서 더 작을 수 있다. 8뉴스 동결·공용 추출 접촉을 감안하면
"완만한 이득 대 중간 공정"의 트레이드오프라 사용자 판단이 필요하다. 데이터 `scratchpad/
mwedge-grids/`(재생성 가능: ffmpeg 192px·2초, 소스 `Downloads/morningwide`).

**§7-bo 후속 — 시간 필터 상보성 확인(`mw-reappear.mjs`). 잔여 FP 벽의 구조 확정.** 에지가
