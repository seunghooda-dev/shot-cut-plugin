# 오디오 단서로 앵커샷·푸티지 경계 보강 (audio-anchor-cue)

사용자 제안(2026-07-30). 화면만으로는 원리적으로 못 잡는 시작 유형이 남아 있고, 그 순간
**오디오에는 판별 정보가 있다**는 관찰에서 출발한다.

## 1. 문제 — 화면으로는 닫히지 않는 잔여

야간 배치(§134~§151) 뒤 실기 블라인드 19회차 중 18회차가 F1 100이고, 유일한 비-100은
**§125 3·4형**이다.

| 유형 | 화면 | 예 |
|---|---|---|
| 3형 인용·전면 카드 직행 | 앵커 없음 | 4/09 202.4 |
| 4형 앵커 VO + b-roll 직행 | 앵커 없음(현장 영상) | 4/07 220.8 |

비전은 이 프레임을 "앵커샷 아님"으로 **옳게** 판정한다. 즉 프롬프트·임계·프레임 선택을
아무리 손봐도 닫히지 않는다 — 판별 정보가 화면에 없기 때문이다.

## 2. 판별력 실측 (2026-07-30, `scratchpad/audio-probe*.py`)

로컬 Whisper(`%LOCALAPPDATA%\ShortFlowStudio\whisper\.venv`, small)로 3회차를 쟀다.

### 사인오프 신호 — 완전 분리

**규칙: `KBC (뉴스)? ◯◯◯입니다`** (리포터 클로징). 창은 경계−22 ~ 경계+1초.

| | 적중 |
|---|---|
| 리포트 종료 경계 직전 | **13/14 (93%)** |
| 같은 아이템 중앙(대조군, 같은 창 길이) | **0/14 오검출** |

### 표적 두 개의 운명은 갈렸다 (6차 실측, 창을 표적에 직접 대고 확인)

| 표적 | 오디오 | 근거 |
|---|---|---|
| **4/09 202.4** (3형) | **닿는다** | 세그먼트 201.4~206.4에 "KBC 뉴스 김정은입니다" — 5차에서 놓친 것은 신호가 없어서가 아니라 **내 매칭이 단방향**(`라벨 ≥ 세그먼트끝−3`)이라 202.4를 탈락시킨 것 |
| **4/07 220.8** (4형) | **못 닿는다** | 앞 아이템이 앵커 단신(기자 없음)이라 사인오프가 **원래 존재하지 않는다**. 창 [199, 223] 전문이 "…추후 발표될 예정입니다"로 끝남 |

**교훈 — 사인오프는 세그먼트 안에서 마지막에 나오므로 세그먼트 끝이 경계보다 뒤일 수 있다.**
매칭은 세그먼트 시작·끝 **양방향 ±8초**로 해야 한다. 단방향 매칭은 있는 신호를 없다고 만든다.

즉 이 신호는 **기자 리포트가 끝나는 경계 전용**이다. 회차당 라벨의 20~36%만 덮지만(4/07 5/14,
1/28 3/15), 그 부분집합은 **결정론적**이라는 점이 핵심 가치다 — 아래 §3.

### 오탐 경로 두 개를 실측으로 제거했다

1. 1차 정규식 `기자입니다`는 **0/10** — 이 방송의 관습은 `KBC ◯◯◯입니다`다. 규칙을
   추측으로 쓰면 신호가 있어도 없다고 결론 낸다.
2. 창 11.7초는 마지막 문장을 잘라 **0/10** — 사인오프는 경계 직전 1~3초에 있으므로 창이
   경계에 닿아야 한다. **"신호 없음"과 "창이 틀림"을 구별할 것.**

### 음향·F0 특징은 기각

mel 프로파일 코사인은 표적 0.996~0.999 vs 리포트중간 0.997~0.998로 **겹친다**. F0 중위값도
회차 내 편차가 부류 간 차이보다 크다. 화자 동일성을 쓰려면 화자 임베딩(별도 의존성)이
필요하고, 지금은 사인오프 텍스트만으로 충분한 판별력이 나오므로 도입하지 않는다.

### 확정 측정 (7차, base 전량 STT · 5회차 · 양방향 ±8초 매칭)

| | 값 |
|---|---|
| 사인오프 검출 | 20건 |
| 라벨 대응 | 19건 |
| 오검출 | **0건**(아래 8차로 규명) |
| 덮은 경계 | 19/63 = **30%** |

### base 전량 STT는 타임스탬프가 최대 8초 드리프트한다 (8차, 결정적)

7차의 유일한 무대응(3/18 720.7)은 오검출이 아니었다. 같은 구간을 **짧은 창으로 다시 들으니**
사인오프는 **725.3~728.8**에 있고 라벨 729.0과 0.2초 차이다. 전량 STT가 8초 앞으로 밀었다.

| 측정 방식 | "KBC 강동일입니다" 위치 |
|---|---|
| 전량 STT(base, 783초 파일) | 717.7~720.7 |
| 짧은 창(small, 입력측 정확 탐색 [722, 734]) | **725.3~728.8** |

**따라서 정밀도는 실효 100%(20/20)이고, 문제는 시각의 정확도다.** 이 드리프트는 설계를
바꾼다 — §150 재스냅은 **뒤로만** 움직이므로, 후보가 8초 **앞**에 놓이면 교정이 불가능하다.

시정 설계 — **2단계 탐색.** ① 전량 base STT로 사인오프가 있는 **대략의 위치**를 싸게 찾고,
② 그 지점 ±12초 창을 입력측 정확 탐색으로 다시 STT해 **정확한 종료 시각**을 얻는다. 짧은 창은
드리프트가 없다(8차 실측). 창이 20개 남짓이라 비용은 회차당 1분 미만 추가.

### 처리량

| 모델 | 실시간 배율 | 15분 회차 전량 |
|---|---|---|
| base | 9.6x | **1.6분** |
| small | 3.5x | 4.3분 |

전량 STT가 1.6분이면 구간 한정 설계의 복잡성을 살 이유가 없다. 단 base로도 사인오프가
잡히는지 확인이 선행 조건이다(측정 진행 중 — `audio-probe5.py`).

## 3. 이 기능의 진짜 가치 — 커버리지가 아니라 결정론

착수 동기는 "§125 3·4형을 잡는다"였으나 실측이 절반만 지지했다(3형 O, 4형 X). 그래서 가치
명제를 정정한다.

야간 배치에서 확인된 이 파이프라인의 최대 불안정 요인은 **§126 실행 간 변동**이다 — 같은
회차·같은 빌드가 비전 표 요동으로 결과를 달리한다(1/06 FP 250은 4실행 중 1회만, 4/09 202.4는
실행에 따라 TP/FN을 오갔다). 회차별 최신 실행이 100이어도 "3연속 100"을 말할 수 없는 이유가
이것이다.

**사인오프는 결정론적이다.** 같은 오디오는 같은 텍스트를 준다. 리포트 경계(전체의 20~36%,
그리고 전형적으로 가장 긴 아이템들의 끝)에 흔들리지 않는 앵커 포인트를 박아 두면, 비전이
요동으로 놓치는 실행에서도 그 경계는 회수된다. 이것이 F1 100의 **재현성**을 올리는 길이다.

정밀도도 충분하다 — 사인오프 세그먼트 끝에서 다음 라벨까지 **0.5~2.8초**(base 전량 STT, 8건
중 7건). §150 재스냅이 최종 정렬을 하므로 이 정도면 경계 후보로 충분하다.

## 4. 설계

### 원칙 — 추가 전용

§149의 교훈: **무료 신호가 비전 판정을 배제 방향으로 뒤집으면 안 된다.** 오디오는 회수
경로에만 쓴다. "비전이 비앵커라 한 곳을 시작으로 승격"만 하고, 앵커 판정을 취소하지 않는다.

### 흐름

1. 분할 시작 시 시퀀스 오디오를 16kHz 모노 WAV로 1회 추출(기존 배관 재사용 — 작업 #18).
2. 로컬 Whisper base로 전량 STT → 세그먼트(텍스트·시작·끝) 목록.
3. 사인오프 정규식에 걸린 세그먼트마다 **그 지점 ±12초 창을 입력측 정확 탐색으로 재STT**해
   정확한 종료 시각을 얻는다(2단계 탐색 — 전량 STT는 최대 8초 드리프트, §2 8차 실측).
   그 뒤 기존 경계와 ±8초 대조해 대응이 없는 것만 남긴다.
4. 남은 후보를 **회수 프로브 목록에 추가**한다(`bandProbeTimes`와 같은 자격) — 그러면 기존
   파이프를 그대로 통과한다: 비전 판정(§139 위치 단서 포함) → §123 중간점 연속성 → §138 병합
   → §150 재스냅. 오디오는 "어디를 보라"만 말하고 **판정은 하지 않는다**.
5. §144와 같은 이유로 후보를 **한 점이 아니라 두 점**(세그먼트 끝, 끝+2s)으로 낸다 — 사인오프
   종료와 실제 컷 사이가 0.5~2.8초로 흔들리므로 고정 오프셋 하나는 컷을 지나칠 수 있다.

**3형(4/09 202.4)은 이 경로로 닿는다** — 사인오프 세그먼트가 그 경계를 품고 있고, 직후 화면이
전면 카드라 비전은 비앵커를 주겠지만, 그 경우를 위해 §125 3형 전용 승격 규칙(사인오프 종료점은
비전 판정 없이 채택)을 별건으로 검토한다. FP 위험이 있어 4단계 실증 뒤에 다룬다.
**4형(4/07 220.8)은 이 경로로 못 닿는다** — 앵커 단신 사이 경계라 사인오프가 존재하지 않는다.
정직하게 미해결로 남기고, 다른 신호(앵커 목소리 화자 동일성)가 필요하다고 기록한다.

### 안전·비용

- 로컬 실행이라 API 키·네트워크 무관(secureStorage 정책 무영향).
- STT 실패·모델 없음은 조용히 건너뛴다 — 오디오는 보조 신호이고, 없으면 현재 동작 그대로다.
- Whisper venv 미설치 환경에서는 기능이 자동 비활성(사용자 설정 불필요).

## 5. 검증 계획

1. 오프라인: 라벨 28회차 전량에 3단계까지 적용 — 사인오프 종료점 vs 라벨의 적중·오검출 표.
   기준: 오검출(라벨 없는 종료점) 회차당 1건 이하.
2. `npm run check` + `npm run check:news` 통과.
3. 실기 3연전: 4/07(4형 표적)·4/09(3형 표적) + 1/28(카나리아 — 100 유지).

## 6. 하지 않을 것

- 전량 STT를 유료 API로 돌리는 것(원클릭 무료화 원칙 — 작업 #35에서 제거한 이유).
- 화자 임베딩·음향 분류(§2에서 판별력 미달로 기각, 근거 있음).
- 오디오로 비전 앵커 판정을 취소하는 경로(§149 위계 원칙 위반).
