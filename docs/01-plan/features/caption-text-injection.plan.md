## 배경

§37에서 "화면 텍스트 자동 주입 불가"로 판정한 근거는 **MOGRT 그래픽 경로**였다 — `TextSegments.importFromJSON` API 자체는 실재하지만 MOGRT 컴포넌트에서 TextSegments 핸들에 도달할 방법이 없었다. 그러나 **캡션(자막) 트랙은 별개의 객체 계층**이고 아직 한 번도 탐사하지 않았다. 캡션 트랙에서 텍스트 주입이 가능하면 뉴스 스타일(C4)의 훅/제목/펀치를 마커 복붙 없이 실제 화면 텍스트로 자동화할 수 있다.

## 성공 기준

1. R1 프로브 — ppro 전역·Sequence·CaptionTrack API 표면에서 캡션 접근 경로 존재 여부 확정.
2. R2 프로브 — (a) 기존 캡션 트랙 읽기, (b) 캡션 트랙 프로그램적 생성, (c) 텍스트 주입(직접 API 또는 SRT import 경유) 중 가능한 조합 확정.
3. 가능 판정 시 — `src/premiere.ts`에 캡션 삽입 함수 + 뉴스 스타일 파이프라인 연결, 단위 테스트 + Host E2E, 게이트 초록.
4. 불가 판정 시 — 시도한 API·에러를 런북에 확정 기록(§37 갱신)하고 종료. 탐사 자체가 산출물.

## 단계

| 구현 | 순수 계층(캡션 계획 빌더) + premiere.ts 삽입 함수 + UI 연결 | npm run check + Host E2E |

## 리스크

- SRT import 경유 경로는 project item은 만들 수 있어도 시퀀스 캡션 트랙 배치 API가 없을 수 있다.
- 캡션은 뉴스 자막바(디자인된 그래픽)와 시각 품질이 다르다 — 베타에서는 "스타일드 캡션"으로 타협하는 것이 목표(완전 대체가 아니라 마커 복붙 제거).
