# 클립별 수동 조정 UI (per-cut-adjust-ui) Planning Document

> **Feature**: D-2 (장기 보류 → 계획 수립) · **Project**: shortflow-studio · **Date**: 2026-07-14
> **상태**: 계획만 수립 — 사용자 승인 후 착수

## 1. 범위

자동 컷이 만든 숏폼의 프레이밍(초점 X/Y·줌)이 마음에 안 들 때, 패널에서 **컷 단위로 미세 조정하고 키프레임을 재적용**하는 UI. 프리미어에서 직접 키프레임을 만지는 것보다 훨씬 빠른 "한 칸 왼쪽으로" 수준의 조정이 목표다.

전제 — 조정에 필요한 API는 전부 이미 있다. `applyShotFocalPositionCorrection`(위치 재기록), `applyShotFocalPositionKeyframes`(전체 재적용), 초점 수학(`focalReframePosition`). 없는 것은 (a) 생성 시점의 초점 계획 영속화, (b) 조정 UI뿐이다.

## 2. 아키텍처

- **계획 영속화**: 숏폼 생성 시 `{ 시퀀스명, 세그먼트, focalSpans[] }`를 localStorage(`shortflow.shotPlans.v1`)에 저장. 순수 직렬화/역직렬화 + 검증(존재하지 않는 시퀀스 정리)은 단위 테스트.
- **UI**(자동 컷 탭 하단 "프레이밍 조정" 섹션):
  - 숏폼 시퀀스 선택 → 컷(스팬) 목록 카드 — 각 카드에 시각 범위·현재 초점·줌 표시.
  - 조정 컨트롤은 X 오프셋(−0.2~+0.2, 0.01 스텝)·Y 오프셋·줌 배율 슬라이더 3개.
  - "재적용" 버튼 → 보정된 스팬으로 위치·스케일 키프레임 재기록(기존 함수 재사용, lockedAccess 트랜잭션).
  - "프레임 미리보기" — 해당 스팬 중앙 시각을 exportFrameToFolder로 뽑아 카드에 표시(§27 검증 루프 재사용).
- **컨트롤러 불필요** — 상태가 localStorage 계획 + DOM뿐이라 index.ts 패널 모듈(`src/adjust-panel.ts`)로 충분. AI 호출 없음.

## 3. 단계

| 단계 | 내용 | 규모 | 예상 |
|---|---|---|---|
| 1 | 계획 영속화(저장·로드·정리) 순수 계층 + 단위 테스트 | 소 | 0.5h |
| 2 | 생성 파이프라인이 계획을 저장하도록 연결(1줄 수준) + 회귀 확인 | 소 | 0.5h |
| 3 | 조정 패널 UI(목록·슬라이더·재적용) + dist 빌드 | 중 | 1~1.5h |
| 4 | Host E2E — 기존 ShotTrack 시퀀스에서 X를 +0.1 조정 → 재적용 → 프레임 export로 이동 확인 → 원복 | 중 | 0.5~1h |

**총 예상 2.5~3.5시간**.

## 4. 검증

- 유닛 — 계획 왕복 직렬화, 손상 데이터 무시, 시퀀스 삭제 후 정리.
- Host — 조정 전/후 프레임의 피사체 X 위치가 의도 방향으로 이동(§27의 얼굴 중심 측정 재사용, ±0.03 허용).

## 5. 리스크

| 리스크 | 완화 |
|---|---|
| 생성 이전 숏폼(계획 미저장)은 조정 불가 | 목록에서 제외하고 "재생성 필요" 안내 |
| 키프레임 재기록이 수동 편집을 덮어씀 | 재적용 전 확인 문구(패널 내 안내), 원복은 계획 원본값으로 가능 |
