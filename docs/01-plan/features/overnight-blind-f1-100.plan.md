# 야간 20시간 배치 — 블라인드 F1 100 계획서

작성 2026-07-29. 사용자 지시("내일 아침까지 멈추지 말고 테스트·학습")에 대한 실행 계획.
시각은 절대시각이 아니라 착수 시점 기준 상대시간(H+n)으로 적는다 — 중간에 지연돼도 순서가 유지되도록.

## 0. 지금 서 있는 자리 (착수 시점 실측)

| 지표 | 값 | 비고 |
|---|---|---|
| ① 코퍼스 전량 오프라인 | 96.5 | 학습셋 포함, 낙관적 |
| ② 홀드아웃 18회차 | P 90 R 80 **F1 84.7** | 무료 경로 일반화 |
| ③ 실기 비전 ON 블라인드 | 24회차 × 1회 · **최소 F1 83.9** | ← 어제 96.3에서 **하락** |

③이 96.3에서 83.9로 내려간 것은 회귀가 아니라 **표본이 1~4월로 넓어졌기 때문**이다(§128:
무료 경로만으로 1~4월 11회차 F1 70.0, 5~7월 대비 급락). 코퍼스가 5~7월에 편중돼 있어
그 분포 밖 회차에서 후보 생성이 무너진다. 이 계획의 중심축은 **그 분포 격차를 닫는 것**이다.

미진단 3회차 — 3/04 F1 95.2(FP 602) · 4/09 F1 90.9(FP 254·282) · **1/28 F1 83.9**(FP 428·456·588, FN 579.5·702.1).

1/28 표 분포 `56=1/4 196=2/4 234=1/4 588=0/4 792=1/4 828=2/4` — 전 후보가 4표를 확보했다.
§132 프레임 결손이 아니다. 특히 **588은 라벨 579.5와 Δ8.5s로 허용치 8초를 0.5초 초과**해
FP·FN을 동시에 만들었다 — 비전 판정이 아니라 **재스냅 결손**이라는 뜻이다. 새 결함 계열이다.

## 1. 단계별 계획

### A단계 (H+0 ~ H+3) — 미진단 3회차 원인 규명

목표는 6개 FP·2개 FN을 각각 **결함 / 라벨 오류 / 원리적 한계** 중 하나로 확정하는 것이다.

- 각 시각의 프레임을 입력측 정확 탐색으로 단발 추출해 육안 판독(컨택시트 타임스탬프는 1~3초 흔들리므로 최종 판정 근거로 쓰지 않는다).
- 588 계열은 재스냅 로그(0.25s 후방 재스냅)를 읽어 **왜 579.5로 당겨지지 않았는지** 확인한다.
- 검증 기준 — 6 FP 전부에 대해 "이 시각의 화면이 무엇인가"를 프레임으로 답할 수 있을 것.

### B단계 (H+3 ~ H+6) — 시정 + 게이트

- A에서 결함으로 확정된 것만 고친다. 라벨 오류로 확정되면 `.items.corrected.json`을 소스로 정정한다.
- 게이트 — `npm run check` + `npm run check:news` 를 파이프 없이 종료 코드로 판정, 통과 후 별도 명령으로 커밋.
- 검증 기준 — 시정 후 해당 회차 실기 재실행에서 그 FP·FN이 사라질 것(1회 실행으로 단정하지 않고 B단계 산출은 D·E에서 재확인).

### C단계 (A·B와 병렬, 상시) — 표본 확보

- 배치8 판독 마감(1/15 · 3/12), 4/16 다운로드 재시도(H.264 1080p 네이티브).
- 신규 회차 추가 확보 — 1~4월 우선(분포 격차가 그쪽에 있으므로).
- 판독 1차는 서브에이전트(프레임 스트립)에 위임하되, **라벨 확정은 넓은 창으로 본인이 재검증**한 뒤에만 반영한다(§97).

### D단계 (H+6 ~ H+10) — 코퍼스 편입 + 재학습

이번 배치의 최대 지렛대다. 블라인드로 소진한 1~4월 회차를 학습셋에 넣어 분포 격차를 줄인다.

- 스캔 캐시 생성 → `register-blind.mjs`로 등록 → **등록한 회차 중 일부는 반드시 `DEFAULT_HOLDOUT`에 남긴다**(남기지 않으면 개선이 지표 ②에 잡히지 않는다 — §100의 함정).
- `train.mjs` 스윕 후 홀드아웃 F1이 커밋 모델을 이길 때만 `--write`.
- 검증 기준 — 지표 ②(84.7)의 상승. 오르지 않으면 반영하지 않고 그 사실을 기록한다.

### E단계 (H+10 ~ H+14) — §126 실행 간 변동 정량화

"3연속 100"을 정직하게 말하려면 회차당 1회 실행으로는 안 된다(같은 빌드가 3/10 97.1↔100,
2/10 76.9↔100으로 흔들린 실측이 있다).

- `variance-run.mjs`로 3회차 × 각 3회 실행, 회차별 최소/중앙/최대를 낸다.
- 검증 기준 — 변동 폭을 수치로 확보. 이 표가 나오기 전에는 어떤 회차도 "100 달성"으로 보고하지 않는다.

### F단계 (H+14 ~ H+18) — 재학습 빌드 블라인드 검증

- D에서 모델이 갱신됐으면 미사용 신규 회차로 블라인드 배치를 돌린다(코퍼스 미포함 확인 필수 — 6/26 오염 재발 방지).
- 검증 기준 — 지표 ③의 최솟값이 83.9에서 올라갈 것.

### G단계 (H+18 ~ H+20) — 마감

- 런북(§134~)·CLAUDE.md 지표 3종 갱신, 커밋·푸시(`newplugin`).
- 아침 보고 — ①②③ 세 수치와 회차당 실행 수, 남은 결손 목록.

## 2. 운영 규칙 (이번 배치에서 반드시 지킬 것)

- **모든 체인에 백그라운드 완료 대기를 붙인다.** 지난 배치에서 대기를 안 붙여 3시간을 놀렸다. 재발 금지.
- 대기 시간은 병렬 작업으로 채운다(다음 회차 다운로드 · 판독 에이전트 · 문서화).
- 실기 실행 중에는 어떤 경로로도 패널에 접근하지 않는다(§40-d 단일 세션).
- API 키는 secureStorage 밖으로 내보내지 않는다 — 비전 진단은 전부 패널 컨텍스트 안에서 실행.
- 지표를 보고할 때 ①②③을 섞지 않는다. 회차당 실행 수와 최솟값을 함께 적는다.
