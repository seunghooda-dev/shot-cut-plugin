

## §126 실행 간 변동 — "전원 100"을 말할 수 없는 이유 (2026-07-29)

3/10을 로그 전용 변경(§124-d 계측)만 넣고 재실행했더니 **97.1 → 100**이 됐다. 코드가 판정 경로를 바꾸지 않았으므로 이건 순수 변동이다. 620s가 이번엔 **후보로도 잡히지 않았고**, 684s는 3표에서 4표로 넘어가 배제됐다.

### 회차별 실행 이력 (같은 회차를 여러 번 돌린 것)

| 회차 | 실행별 F1 | 비고 |
|---|---|---|
| 3/24 | 96.3 · 96.3 · 96.6 · 96.3 · **100** · **100** | 앞 4회는 서로 다른 원인(FN 920 / FN 248 / FP 78 / FP 90) |
| 1/20 | 92.3 · **100** | 1회차만 격자 발동 |
| 2/10 | 76.9 · **100** | §124 수정 |
| 3/10 | 97.1 · **100** | 코드 변경 없음(로그 전용) |
| 4/20 | 100 · 100 · 100 | |

### 결론 — 지표 문장을 바꾼다

**"블라인드 N회차 전원 F1 100"은 쓰지 않는다.** 실행 1회 결과를 회차 성적으로 승격하는 문장이기 때문이다. 대신 이렇게 적는다.

- **회차당 실행 수를 명시한다** — "20회차 × 1회 실행, 최소 F1 96.3"
- **최솟값을 함께 적는다** — 평균이나 최댓값만 적으면 변동을 숨긴다
- **완료 조건은 최솟값 기준으로 판정한다** — CLAUDE.md의 "미학습 신규 회차 3연속 F1 100"은 **같은 회차 복수 실행에서 전부 100**이어야 충족된 것으로 본다

### 변동의 출처

관측된 변동은 전부 **후보 생성 단계**에서 나온다 — 같은 회차·같은 빌드인데 화면 매칭 후보 수(20 vs 22), 확정 후보 수(7 vs 9 vs 10), 뱅크 적합도(격자 발동 여부)가 실행마다 달랐다. 뒤이은 비전 검증·회수는 그 입력에 따라 달라진다.

**그래서 코퍼스 확장이 변동 자체를 줄이는 유일한 구조적 접근이다.** 분포 밖 회차는 뱅크 거리가 문턱 근처에 몰려 있어 작은 요동이 후보 집합을 크게 바꾼다. 1~4월 회차를 학습·뱅크에 넣으면 그 거리가 문턱에서 멀어진다.
