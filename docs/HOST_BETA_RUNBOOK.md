

## §122 내보내기 산발 실패 규명 + 블라인드 명단 정정 (2026-07-29)

### 4/20 846 오배제 — 9회 재현 실패 끝에 워밍업으로 소멸

전날 미규명으로 남긴 "진짜 앵커 846이 4표 전원 합의로 배제" 사건을 층별로 끝까지 갈랐다.

| 검증 | 결과 |
|---|---|
| 패널 내보내기 vs 로컬 ffmpeg 추출(850·853) | **화면 일치** — 시각 충실도 정상 |
| 같은 시각 3회 반복 내보내기 | **바이트 동일** — 내보내기 자체는 결정적 |
| 모델 단독 4프레임 | 3/3 정확(846=2표) |
| 운영 청크 정확 재현(806·846·882 각 4장) | 5/5 정확(846=2표) |
| **실제 참조 예시 5장 주입** 후 같은 청크 | 4/4 정확(846=2표) |

**참조 예시를 못 읽고 있었던 것이 1차 진단의 오류였다.** 저장 키는 `shortflow.anchor-corpus.v1`인데 `shortflow.anchorExemplars`를 읽어 "예시 0개"로 결론냈다. 실제로는 5장(7/15 회차 계열)이 주입되고 있었다. 다만 그것을 넣어도 판정은 여전히 정확했다.

**진짜 원인은 내보내기였다.** 결정성 측정에서 **rep0의 첫 2장만 `exportSequenceFrame`이 `true`를 반환하고도 파일을 남기지 않았고**(읽기 12회×400ms 재시도에도 부재), 이후 전부 성공했다. 시퀀스 활성화 직후의 워밍업 문제다. 검증 경로에 **버릴 프레임 1장으로 파이프라인을 깨우는 워밍업**을 넣고 4/20을 재실행하자 **배제 0 · 846=2표 · 14/14 F1 100**이 나왔다(직전 두 실행은 846=4표 배제).

후보 시각이 실행마다 달라지므로(§121-b) 워밍업 단독 효과로 단정하지는 않는다. 다만 ①내보내기 산발 실패가 실측됐고 ②그 자리에서 표가 통째로 날아가는 경로가 실재하며 ③워밍업은 무해하므로 채택한다.

### 계측 추가 — 배제 판정 상세

배제된 후보에 대해 **프레임별 판정**(offset·앵커 여부·신뢰도)을 활동 로그에 남긴다. 표 수만으로는 "어느 프로브가 어떻게 판정됐는지"를 알 수 없어 이번 규명에 하루가 걸렸다. 회수 경로에는 이미 있던 것(§110-b)을 검증 경로에 이식했다.

### 블라인드 명단 정정 — 6/26은 학습셋이었다

6/26을 12회차 블라인드로 돌렸으나 **`training-data/news-anchor/`에 있고 `DEFAULT_HOLDOUT`에는 없는 회차**였다. 즉 학습에 쓰인 회차다(로그의 "학습 모델 14"가 정답 14개를 그대로 재현한 것이 in-sample 신호였다). 블라인드 명단에서 제외한다 — **진짜 블라인드는 11회차 121아이템**이다.

**규약 추가**: 새 회차를 블라인드로 쓰기 전에 코퍼스 포함 여부를, 포함이면 홀드아웃 여부를 먼저 확인한다. 확인 없이 돌린 회차는 지표로 세지 않는다.
