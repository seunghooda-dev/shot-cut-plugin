# 파일 쌍 학습 UX (style-pair-learning-ux) Planning Document

> **Feature**: D-3 (장기 보류 → 계획 수립) · **Project**: shortflow-studio · **Date**: 2026-07-14
> **상태**: 계획만 수립 — 사용자 승인 후 착수

## 1. 범위

스타일 학습의 **코어는 이미 완성**돼 있다 — `src/style-corpus.ts`(addStyleExample/loadStyleCorpus/clearStyleCorpus) + 자동 컷 few-shot 주입. 그러나 현재 UX는 "원본 SRT 불러오기 → 원본으로 지정 → 숏폼 SRT 불러오기 → 숏폼으로 학습"의 4단계 순서를 사용자가 기억해야 한다. 이를 **파일 쌍 한 번 선택으로 끝나는 등록 흐름**으로 바꾸고, 학습된 예시를 관리(목록·삭제)할 수 있게 한다.

## 2. 아키텍처

- **한 번에 쌍 등록**: "샘플 쌍 등록" 버튼 하나 → 파일 피커에서 원본 SRT와 숏폼 SRT를 **동시에 2개 선택**(또는 순차 2회 — UXP 다중 선택 가용성에 따라) → 길이 비교로 어느 쪽이 원본인지 자동 판별(원본이 항상 김) → 정렬·학습·토스트까지 자동.
  - 판별 순수 함수 `classifyStylePair(a, b) → { original, short } | null`(총 길이·cue 수 비교, 애매하면 null 반환하고 사용자에게 순서 확인) — 단위 테스트.
- **SRT 없는 숏폼(영상만 있는 경우)**: v1 범위 밖 — "숏폼 SRT가 필요합니다. 음성·자막 탭에서 STT로 만들 수 있습니다" 안내만. (STT 자동 연결은 비용이 있어 사용자 확인 필요 — 후속.)
- **코퍼스 관리 UI**: 학습된 예시 목록(원본/숏폼 이름·cue 수·등록일) + 예시별 삭제. `style-corpus.ts`에 `removeStyleExample(id)` 추가(순수, 단위 테스트).
- 기존 4단계 흐름은 그대로 두되(회귀 0) 새 쌍 등록 버튼을 우선 노출한다.

## 3. 단계

| 단계 | 내용 | 규모 | 예상 |
|---|---|---|---|
| 1 | `classifyStylePair` 순수 함수 + `removeStyleExample` + 단위 테스트 | 소 | 0.5~1h |
| 2 | 쌍 등록 UI(피커 2파일 → 판별 → 학습) + 코퍼스 목록·삭제 UI | 중 | 1~1.5h |
| 3 | Host 스모크 — 합성 SRT 쌍(newswide 자막에서 부분 추출로 제작)으로 등록→목록→자동 컷 few-shot 반영 확인→삭제 | 중 | 0.5~1h |

**총 예상 2~3.5시간**. 실제 사용자 샘플 검증(C2)은 사용자가 파일 쌍을 제공할 때 별도 수행.

## 4. 검증

- 유닛 — 판별(명확·애매·동일 길이), 삭제 후 코퍼스 정합, 손상 항목 무시.
- Host — 등록 흐름 클릭 스모크 + 자동 컷 스캔 프롬프트에 예시가 주입되는지(기존 검증 로직 재사용).

## 5. 리스크

| 리스크 | 완화 |
|---|---|
| UXP 파일 피커 다중 선택 미지원 | 순차 2회 선택으로 폴백(순서 무관 — 판별 함수가 처리) |
| 원본/숏폼 판별 오판(길이 비슷) | 애매하면 자동 판별 포기하고 순서 확인 다이얼로그 |
| 예시 과다로 프롬프트 비대 | 기존 few-shot 주입의 상한 유지(최근 N개) |
