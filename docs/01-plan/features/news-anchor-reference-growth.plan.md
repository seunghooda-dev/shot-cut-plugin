# Plan — 참조 뱅크 성장(news-anchor-reference-growth)

> §100 처방 ①. 고정 참조 뱅크의 용량 한계를 "제품이 스스로 참조를 늘리는 경로"로 푼다.

## 1. 문제

미학습 신규 회차 2026-07-23에서 무료 분할이 무너졌다 — 정답 12아이템 중 **4개**만 생성(F1 47.1, 실기 비전 ON 50.0). 같은 빌드로 직전 회차 7/20·7/21·7/22는 F1 100이다.

원인은 §100에 실측으로 정리돼 있다. 요약하면 세 가지다.

- 참조 뱅크(평일 13장)가 이 회차 앵커샷을 못 알아본다 — 최소거리 0.0784(7/22) → **0.1179**(7/23).
- 뱅크 거리가 **학습 모델의 특징이기도 해서**(`news-visual-cut.ts` 모델 특징 146) 후보 생성과 모델이 **같은 원인으로 함께** 무너진다. 이중화처럼 보였지만 이중화가 아니다.
- 매처는 "왼쪽에 앵커가 있는가"가 아니라 **"화면 전체가 참조와 닮았는가"**를 잰다. 가중치 `1/(√std+8)` 아래에서 **배경이 총 가중치의 68%**를 차지하고, 배경은 매 컷 달라진다. 놓친 8샷과 잡은 4샷이 육안으로 구분되지 않는 이유다.

## 2. 이미 기각된 대안 (실험 완료 — 다시 시도하지 말 것)

| 시도 | 결과 | 판정 |
|---|---|---|
| 모델에서 뱅크 거리 특징 제거 후 재학습 | 홀드아웃 최고 77.8 < 기준선 82.6, 7/23도 47.1→44.4 | **기각** — 현재 특징 공간에 뱅크 외 판별 정보가 없다 |
| 앵커 영역만 매칭(열6 행0~8) + 재학습 | 7/23 47.1→**75.0**이지만 전량 94.4→**91.2**, 망가진 회차 4→11 | **기각** — 1회차 살리고 7회차 깬다 |
| 전체화면 후보 ∪ 영역 후보 | 7/23 **37.5**로 악화 | **기각** — 거리 척도가 달라 적응 임계가 깨진다 |

**결론**: 어떤 고정 설정도 "배경 강건성"과 "앵커 특이성"을 함께 만족시키지 못했다. 튜닝이 아니라 구조가 답이다.

## 3. 목표

- **주 목표**: 미학습 신규 회차에서 무료 경로 F1 **≥ 90**(현재 47.1). 코퍼스 82회차 전량은 **94.4 이상 유지**(후퇴 금지).
- **부 목표**: 배포판 사용자가 개발자 개입 없이 자기 방송사·자기 포맷에 맞춰 정확도를 올릴 수 있을 것.
- **비목표**: 얼굴 인식·오디오 등 새 특징 도입(§100 처방 ④ — 별도 과제), 모닝와이드 지원.

## 4. 설계 방향 (Design 단계에서 확정)

### 4-a. 사용자가 확인한 결과를 참조로 승격

분할 결과를 사용자가 검토하는 시점이 이미 워크플로에 있다("검토 후 '일괄 내보내기'를 누르세요"). 그 확인 행위를 학습 신호로 쓴다.

- 사용자가 결과를 승인하면, 확정된 아이템 시작 프레임의 격자를 **로컬 참조 뱅크**에 추가한다.
- 경계를 수동으로 고쳤다면 **고친 위치**의 격자를 추가한다(오답 교정이 그대로 정답 참조가 된다).
- 로컬 뱅크는 내장 뱅크와 **분리 저장**하고, 매칭 시 합쳐 쓴다. 내장 뱅크는 건드리지 않으므로 초기화가 항상 가능하다.

미해결 질문 — 승인 UI를 새로 만들 것인가, 기존 내보내기 클릭을 암묵적 승인으로 볼 것인가. 후자는 공짜지만 "확인 안 하고 눌렀는데 오답이 학습됨" 위험이 있다.

### 4-b. 뱅크가 커질 때의 가중치 재계산

가중치는 참조들의 셀별 std에서 나오므로, 참조가 다양해지면 **배경 셀의 std가 커져 가중치가 자동으로 내려간다**. 즉 4-a는 배경 지배 문제(68%)를 **부수적으로 완화**한다 — 별도 영역 마스킹 없이. 이 효과의 크기는 Design 단계에서 시뮬레이션으로 확인한다(기존 코퍼스에서 참조 13→30→60장으로 늘려가며 배경 가중치 비중과 전량 F1을 측정).

### 4-c. 상한과 안전장치

- 로컬 참조 수 상한(예: 포맷당 40장) — 무한 성장 시 거리 계산 비용과 과적합 위험.
- 추가 전 중복 제거(기존 참조와 거리 < ε이면 버림) — 같은 회차 앵커샷 12장이 그대로 쌓이면 그 회차에만 쏠린다.
- **뱅크 오염 복구 경로**: "학습된 참조 초기화" 버튼. 사용자가 잘못된 결과를 반복 승인하면 정확도가 내려갈 수 있으므로 되돌릴 수단이 반드시 있어야 한다.
- 로컬 뱅크 추가 후 **경고 임계(§100 처방 ③)가 자동으로 낮아지는지** 확인 — 뱅크가 맞아 들어가면 경고도 사라져야 한다.

## 5. 검증 계획

| 단계 | 방법 | 통과 기준 |
|---|---|---|
| 시뮬레이션 | 코퍼스에서 참조를 13→60장으로 늘려가며 전량·홀드아웃 F1 측정 | 전량 ≥94.4 유지 + 7/23 개선 |
| 홀드아웃 | 7/23을 학습에서 제외한 채, 7/24·7/25를 "사용자가 승인한 회차"로 주입한 뒤 7/23 재측정 | 7/23 F1 ≥90 |
| 회귀 | `npm run check` + `npm run check:news` | 그린 |
| 실기 | 7/23·7/24 Premiere 실전(비전 ON) | 경고 소멸 + 아이템 수 정답 일치 |

7/24·7/25는 라벨이 없으므로 **먼저 라벨링이 필요하다**(7/23과 같은 절차 — 서브에이전트 1차 판독 + 본인 재검증).

## 6. 위험

- **오답 학습**: 사용자가 잘못된 분할을 승인하면 뱅크가 오염된다. 4-c의 초기화 경로가 완화책이지만, 근본적으로는 "승인"의 의미를 UI에서 분명히 해야 한다.
- **포맷 라우팅 간섭**: 로컬 참조가 늘면 `selectAnchorMatcher`의 뱅크 선택이 흔들릴 수 있다(평일 회차가 신형 뱅크로 라우팅되는 등). 라우팅 임계 `ROUTE_MAX_DIST=0.05`의 재검토가 필요할 수 있다.
- **효과 미달**: 4-b의 배경 가중치 완화가 기대만큼 크지 않을 수 있다. 시뮬레이션에서 먼저 확인하고, 미달이면 영역 제한을 **로컬 뱅크에만** 적용하는 혼합안을 검토한다.
