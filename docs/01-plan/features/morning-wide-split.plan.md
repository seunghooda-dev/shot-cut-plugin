# Plan: 모닝와이드 분할 (morning-wide-split)

작성 2026-08-04. 사용자 지시 — "오늘로 8뉴스 마감하자, 이제 모닝와이드도 분할을 해야 해."

## 1. 배경과 목표

8뉴스 자동 분할은 2026-08-04 기준 실기 블라인드 45회차 중 43회차 F1 100(신규 미학습 7회차
연속 100)으로 신규 회차 검증을 종결한다. 다음 대상은 **KBC 모닝와이드**다.

- 목표: 모닝와이드 회차의 아이템 경계 F1 100 (측정 규약은 8뉴스와 동일 — `lib.mjs boundaryF1`,
  ±8초, 지표 ①/②/③ 혼용 금지).
- 소스: KBC 유튜브 채널(UCVcLszfUBN9rTmc0A0uDRSQ)의 "모닝와이드 다시보기" 재생목록
  (PLksVplp0JSVp7F-n9fBIw6vesQUHETP86). 평일 1회차, 회당 844~1324초(14~22분) — 8뉴스(약
  15분)와 길이대가 겹친다.

## 3. 아키텍처 — 프로그램 프로필

핵심 원칙은 "라벨 분리"가 아니라 **자산 분리**다.

- **프로필** = {학습 모델(가중치), 참조 뱅크, 비전 프롬프트, 하단 띠 기하·줄 수 규칙,
  오프닝/사인오프 규칙, 코퍼스·홀드아웃, 실측 지표 명단}.
- **엔진 공유** — 2초 격자 luma 스캔, 후보∪모델, 비전 검증(4프레임 4표·재수집), 회수(§110
  띠·§171 스윕·되짚기·§170 칼럼), §138 병합, §148 재스냅, §190-b·d 지연 재시도는 프로그램
  무관 공통 코드로 유지한다.
- **8뉴스 프로필 동결** — 기존 검증 자산(45회차)이 모닝와이드 작업의 어떤 변경에도 영향받지
  않는 구조로 배선한다. 8뉴스 경로의 코드 diff 0이 원칙이며, 공통 엔진을 건드릴 때는
  `npm run check:news`(8뉴스 회귀 게이트) 통과를 커밋 조건으로 유지한다.
- **오선택 가드** — 두 프로그램은 길이대가 겹쳐 길이 판별이 약하므로, 1차 방어는 버튼의
  명시성이고 2차 방어는 실행 초기 스캔에서 프로필 불일치 신호(오프닝 구조·띠 기하가 프로필
  기대와 크게 다름)를 감지하면 §189 #2 패턴의 확인창을 띄우는 것이다(구현은 P3에서 실측 후
  판단 — 신호가 약하면 넣지 않는다, 추측성 코드 금지).

## 4. 지표·데이터 분리 규약 (혼용 금지)

- 코퍼스 `training-data/morning-wide/` 신설 — 8뉴스(`training-data/news-anchor/`)와 완전 분리.
- 홀드아웃 명단도 별도(`train.mjs`의 모닝와이드 전용 DEFAULT_HOLDOUT 계열). **새 회차 추가
  시 홀드아웃 동시 등록 규칙 동일 적용.**
- 실기 블라인드 명단 별도. 두 프로그램 점수를 합산·병기하지 않는다(§126·§162 교훈 승계).
- 다운로드 폴더 분리 — `Downloads/morningwide/`(파일명 `YYYYMMDD_Www_mw.mp4`),
  8뉴스 `Downloads/blind/`와 섞지 않는다.

## 5. 단계 (각 단계 → 검증 방법)

- **P1. 코퍼스 수집** — 최신 10회차(7/22~8/4) 다운로드(진행 중). 최신 2회차(8/3·8/4)는
  코퍼스에 넣지 않고 실기 블라인드 후보로 보류. → 검증: 파일 10개·H.264·재생 확인.
- **P2. 구조 관찰·라벨링** — 8회차(7/22~7/31) 프레임 스트립 1차 판독(서브에이전트 위임 가능,
  라벨 확정은 본인 재검증 — 8뉴스 측정 규약 승계). 오프닝 구조·앵커 위치·띠 디자인·코너
  구조를 기록하고 라벨 JSON 작성. → 검증: 라벨 상호 검토(FN은 이웃 라벨 목록 필수).
- **P3. 프로필 규칙 작성** — P2 관찰로 모닝와이드 프로필(오프닝 제외 규칙·비전 프롬프트
  변형·띠 규칙) 초안. "아이템 시작=앵커샷" 가정의 유효성을 이 단계에서 판정한다. → 검증:
  오프라인 후보 생성 F1(코퍼스 8회차).
- **P4. UI·배선** — "뉴스 분할" → "8뉴스 분할" 개명 + "모닝와이드 분할" 버튼 신설, 분할
  진입점에 프로필 파라미터 스레딩. 공통 설정(화질·내보내기)은 공유. → 검증: `npm run check`
  + `check:news` 무하락 + UI 계약 테스트.
- **P5. 학습·홀드아웃** — 모닝와이드 전용 학습(코퍼스 6 + 홀드아웃 2로 시작). → 검증:
  홀드아웃 F1 게이트.
- **P6. 실기 검증** — 8/3·8/4(P1 보류분)와 이후 신규 업로드로 실기 비전 ON 블라인드.
  채점 전 검문 2종(비전 검증 시작 존재·한도 0건)·§151 오염 검사 동일 적용. → 완료 조건:
  8뉴스와 동일(미학습 신규 3회 연속 100, 회차당 복수 실행).

## 6. 위험과 미지수

- **업로드가 전체 방송이 아닐 수 있다** — 재생목록 영상이 로컬 세그먼트/코너 컷본(14~22분)
  형태다. 사용자의 실제 작업 대상과 일치하는지 P2 관찰 후 확인 필요. 불일치면 수급 재협의.
- **"아이템 시작=앵커샷" 가정 약화 가능** — 모닝와이드는 코너·리포터 진행 비중이 클 수
  있다. 7/09 대담 코너(§190-c)·7/29 칼럼(§170)에서 본 구조 유형이 기본형일 가능성. P2에서
  구조 분포를 먼저 재고 P3 설계에 반영한다.
- **주말 부재** — 평일만 업로드되므로 주말 포맷 대응은 범위 밖(8뉴스의 주말 뱅크 같은 분기
  불필요할 수 있음).

## 7. P2 초기 관찰 — 7/23 회차 전 구간 (2026-08-04, 컨택트 시트 5장·8초 간격)

- **골격은 8뉴스와 동일하다**: 오프닝 CG → "오늘의 주요 뉴스" 예고 카드(누적형, 제외 대상)
  → **앵커샷이 아이템을 연다** → 리포트(b-roll·인터뷰·스탠드업·CG 카드) → 엔딩 "구독하기"
  CG. §6의 "앵커샷 가정 약화" 우려는 이 회차에서는 기각 — 대담·매거진 세트 없음.
- **앵커샷 구도 2종, 둘 다 앵커는 왼쪽**(8뉴스 관례와 부합). ①풀샷(좌 앵커 + 우 주제 CG)
  ②분할 구도(좌 1/3 앵커 + 우 2/3 콘텐츠 이미지) — 후반 단신 러시에서 ②가 연속 사용된다.
  ②는 8뉴스에 없는 구도라 비전 프롬프트·참조 뱅크에 신규 등록 필요.
- **하단 띠**: 좌측 주황 "MORNING WIDE" 로고 박스 + 흰 바탕 검정 1줄 헤드라인. 인터뷰
  인용은 명패+인용 2줄. 8뉴스와 디자인이 달라 띠 기하 재측정 필요. 리포트 중 좌상단 코너
  태그 지속 표시(8뉴스와 유사).
- **아이템 밀도가 높다**: 1190초에 15개 내외(후반 단신은 아이템당 30~60초). 8뉴스(약 15분
  11개)보다 조밀 — 병합·재스냅 파라미터의 프로그램별 분리가 필요할 수 있다(P3에서 판정).
- 날씨는 별도 기상 코너가 아니라 앵커 단신 + b-roll 형태.
- 우하단에 방송 시각(07:12 등) 상시 표시 — 격자 신호에 영향 없는 위치인지 P3에서 확인.

### 7-b. 7/24 회차 1차 판독 (에이전트 위임 + 유보 2곳 본인 재검증, 2026-08-04)

- **경계 19건**(8초 격자 1차 17 높음 + 2 유보 → 유보 2곳을 2초 간격 시트로 본인 재검증해
  **둘 다 성립 확정**: 394s·980s). 980s는 짧은 앵커샷이 8초 격자 타일 사이에 빠졌던 사례 —
  제품의 2초 격자 스캔이면 포착된다. 라벨 최종 확정은 전 경계 2초 정밀 패스에서.
- **띠 과분할 함정(P3 핵심 반영 사항)**: 띠 헤드라인이 한 아이템 안에서 여러 번
  바뀐다(도시철도 아이템에서 5회 교체 실측). **띠 문구 변화를 경계 신호로 쓰면 과분할** —
  8뉴스 §110 띠 이벤트 회수 규칙을 그대로 이식하면 안 된다. 아이템 수준에서 유지되는 것은
  **좌상단 주제 태그**다(긴 리포트형의 경계 단서로 띠보다 강함).
- 구성 2부 구조: 전반 리포트형(스탠드업·인터뷰 포함) + 후반 앵커 단신 연속 블록(아이템당
  24~56초). 이 회차 앵커샷은 사실상 전부 분할 구도(7/23에는 풀샷도 있었음).
