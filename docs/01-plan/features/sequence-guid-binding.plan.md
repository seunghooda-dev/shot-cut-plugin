## 문제

내보내기·정리·복제 경로가 시퀀스를 **이름 문자열**로 결속한다(`queueSequenceExportsByName`
등). 프로젝트 전환·동명 시퀀스 상황에서 **다른 시퀀스를 내보내거나 지울 수 있다** —
파괴적 오동작 위험. §184 감사가 재설계 규모로 분류해 보류했던 항목이다.

## 목표 (성공 기준)

1. 내보내기·정리 대상 해석이 이름이 아니라 **시퀀스 GUID**(`sequence.guid` — UXP 제공
   여부 실기 프로브로 선확정)를 1차 키로 쓴다. 이름은 표시·로그 전용.
2. 동명 시퀀스 2개가 있는 프로젝트에서 정확한 대상만 내보내지는 실기 검증 1회.
3. 기존 이름 기반 호출부(뉴스 분할 생성 직후 내보내기)는 GUID를 **생성 시점에 포착**해
   전달 — 이름 재조회 제거.
4. 게이트: 단위(모의 프로젝트 동명 케이스) + `npm run check` + host:smoke:full 그린.

## 비목표

- 마커·복구 저널 등 다른 이름 결속 지점의 일괄 전환(범위 폭발 방지 — 내보내기·정리만).
- 저장 상태(설정·복구 저널)에 GUID 영속화(프로젝트 간 이식성 문제는 별도 검토).

## 단계 → 검증

   되고, 대안(생성 직후 객체 참조 유지)으로 회귀한다 — §188-b 교훈: 신호원부터 확정.)*

   재열기 불변성은 다음 로테이션 경계에서 확인(뉴스 분할 흐름은 단일 세션이라 세션 내
