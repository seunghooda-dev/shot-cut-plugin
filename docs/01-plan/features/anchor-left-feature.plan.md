# 앵커 왼쪽 규칙 특징화 (anchor-left-feature) Planning Document

> **Feature**: 과분할(FP) 억제 — 가운데 인물 오검출 필터 · **Project**: shortflow-studio · **Date**: 2026-07-21
> **근거 규칙**: 사용자 검수 확립 "앵커는 항상 화면 왼쪽, 가운데 인물은 인터뷰이/발언자"(feedback-anchor-left-position)

## 1. 범위

§74 기준 전체 51회차 F1 90.2에서 남은 오차의 주범은 **과분할 FP 83** — 발언·회견 등 가운데 인물 장면을 앵커로 오인해 아이템을 쪼갠다(6/10에서 4건 등). 재현율은 94(신규 5회차는 100)로 충분하므로, **정밀도만 올리는 후처리 필터**를 넣는다.

핵심 제약: 하이브리드 확정은 `freeAnchorTimes(화면매칭) ∪ modelStarts(모델)` — 모델은 후보를 **추가만** 할 수 있고 제거할 수 없다. 따라서 모델 재학습으로는 FP를 못 줄인다(§74 게이트에서 실측). 해법은 확정 이후의 **왼쪽 영역 검증 필터**다.

## 2. 아키텍처

- **왼쪽 영역 매처**: 기존 참조 뱅크(평일 13·신형 18)의 그리드에서 **왼쪽 열(16열 중 0~6열)만** 추린 부분 그리드로 별도 매처를 만든다(`buildAnchorMatcher` 재사용 — 셀 수만 다름). 앵커 리드는 왼쪽 열이 참조와 강하게 일치(데스크+앵커), 가운데 인물 장면은 왼쪽이 배경/군중이라 거리가 크다.
- **필터 함수** `filterAnchorTimesByLeftRegion(times, samples, leftMatcher, threshold)`: 확정된 각 시각의 샘플(±2s 창 최소거리)에 대해 왼쪽 거리 > 임계면 제외. 임계는 코퍼스 학습 회차에서 튜닝하고 홀드아웃으로 검증(파이프라인 게이트 방식 그대로).
- **적용 지점**: `hybridAnchorTimes` 결과 직후(index.ts 원클릭 경로 + scripts/news-train/lib.mjs `predictItemStarts` 동일 적용 — §71-e 정합 원칙).
- **안전장치**: 필터로 앵커가 3개 미만이 되면 필터 미적용(참조가 안 통하는 미지 포맷에서 재현율 붕괴 방지 — collectAnchorCandidates의 확대 폴백과 같은 철학).

## 3. 단계

| 단계 | 내용 | 규모 |
|---|---|---|
| 1 | `buildLeftRegionGrids()`(열 슬라이스) + `filterAnchorTimesByLeftRegion` + 유닛 테스트 | 소 |
| 2 | lib.mjs `predictItemStarts`에 필터 통합 + 임계 스윕(오프라인, 51회차·홀드아웃) | 소 |
| 3 | 판정 — 전체 F1·홀드아웃 F1 모두 개선 시에만 index.ts 반영(미달이면 미반영·정직 보고) | 소 |
| 4 | 게이트(npm run check)·런북 §75·커밋 — 실기 검증은 다음 신규 회차 테스트에서 겸행 | 소 |

전부 오프라인(캐시 기반) — 호스트 불필요, 총 1~2시간.

## 4. 검증(성공 기준)

- 전체 51회차: FP 83 → **감소**, R 94 유지(±1), F1 90.2 → **상승**.
- 홀드아웃 4회차(0709·0711·0712·0628): 현행 84.9 대비 **하락 없음**.
- 유닛: 왼쪽 매칭 필터(앵커 통과·가운데 인물 제외·3개 미만 폴백) 포함 1820+ 그린.
- 기준 미달 시 반영하지 않고 결과만 기록(게이트 원칙).

## 5. 리스크

| 리스크 | 완화 |
|---|---|
| 앵커가 왼쪽이 아닌 특수 컷(2인 데스크 등) 오제외 | ±2s 창 최소거리 사용 + 임계 보수 튜닝 + 홀드아웃 검증 |
| 미지 포맷에서 필터가 전멸시킴 | 3개 미만 폴백(필터 해제) |
| 왼쪽 열에 자막바/수화 창이 겹침 | 참조 그리드도 같은 조건이라 상쇄 — 실측으로 확인 |

## 6. 실험 결과 (2026-07-21) — ❌ 기각

구현·스윕 완료 후 **모든 임계에서 성능 하락** — 반영하지 않음(게이트 원칙).

| 임계 | 전체 F1 | FP | R |
|---|---|---|---|
| OFF(현행) | **90.2** | 83 | 93.8 |
| 0.06 | 87.8 | 74 | 88.2 |
| 0.07~0.12 | 77.8~86.0 | 60~69 | 70~84 |

**원인**: 왼쪽 열에는 앵커의 **몸(매일 바뀌는 의상)**이 포함된다. luma 그리드 왼쪽 슬라이스는 "왼쪽에 사람이 있다"가 아니라 "왼쪽 픽셀이 참조와 같다"를 재므로, 전체 프레임보다 의상 변화에 **더** 민감해져 진짜 앵커를 오제외한다(FP 소폭 감소 대비 R 급락). 규칙 자체(앵커=왼쪽)는 유효하나 이 특징화로는 구현 불가.

**후속 방향(미착수)**: 사람-존재 신호가 필요 — 왼쪽/가운데 영역의 **시간적 미세 움직임**(발화 중 인물은 국소 변화 지속) 비교, 또는 비전 판정 재도입 시 위치 프롬프트. 코드 전량 회귀(게이트 1820 그린), 스윕 스크립트는 scratchpad/sweep-left.mjs 보존.
